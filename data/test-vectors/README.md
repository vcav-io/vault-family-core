# VSSP Test Vectors

## Purpose

This directory contains deterministic test vectors for independent VSSP implementation verification. Vectors enable external implementers to validate their protocol implementation without access to internal source code.

## Vector Categories

### Positive Vectors

Positive vectors represent valid protocol operations that MUST succeed:

- Receipt signature verification (`receipt_v2_positive_01.json`, `receipt_v2_positive_02.json`)
- Session handoff signature verification (`handoff_positive_01.json`)
- Agreement hash computation (`agreement_hash_positive_01.json`, `agreement_hash_positive_02.json`)
- `pair_id` derivation (`pair_id_positive_01.json`, `pair_id_positive_02.json`)
- Canonicalization (`canonicalization_positive_01.json`)
- Contract schema validation (`contract_positive_01.json`)

### Negative Vectors

Negative vectors represent invalid operations that MUST be rejected:

- Wrong domain prefix (`receipt_v2_negative_01.json`, `handoff_negative_01.json`)
- Tampered receipt after signing (`receipt_v2_negative_02.json`)
- Unsorted participants produce different hash (`agreement_hash_negative_01.json`)
- Non-ASCII `agent_id` edge case (`pair_id_negative_01.json`)
- Non-canonical JSON forms (`canonicalization_negative_01.json`)
- Malformed contract hash fields (`contract_negative_01.json`)

### Standalone Files

- `receipt_v2_vector_01.json` -- A complete signed receipt that passes `vcav-verify` with `keys/vault.pub`. Suitable for end-to-end verifier integration testing.

### Receipt v3 vectors

Specified in `docs/receipt-v3.md` and generated by
`cargo run -p receipt-core --example vcav-generate-v3-vectors`:

- `jcs_rfc8785_testdata.json` -- RFC 8785 reference test data (cyberphone, Apache-2.0; sources in `jcs_rfc8785_cyberphone/`)
- `jcs_rfc8785_numbers.json` -- RFC 8785 Appendix B number serialisations
- `jcs_v3_profile.json` -- v3 canonicalisation profile (accepted and rejected inputs)
- `input_commitment_v3.json` -- input commitments v3
- `contract_hash_v2.json` -- contract hash v2
- `receipt_v3_positive_01.json`, `receipt_v3_positive_02.json` -- signed v3 receipts
- `receipt_v3_negative.json` -- v3 receipts that must be rejected, with error classes

Canonicalisation cases give JSON text (`input_json`), the expected canonical string and the
SHA-256 (lowercase hex) of its UTF-8 bytes, so they can be consumed directly from TypeScript.

## Naming Convention

Vectors follow the pattern:

```
<domain>_<type>_<number>.json
```

Examples:
- `receipt_v2_positive_01.json`
- `handoff_negative_01.json`
- `pair_id_positive_02.json`

## Format

Each vector file is a JSON object containing:

- `description`: Human-readable description of what the vector tests.
- `input`: The input data for the operation.
- `expected`: The expected result (output value for positive, error class for negative).
- `schemas`: Array of schema `$id` values that apply.

## Key Material

Test keys are in `keys/`. They are derived from known fixed seeds and are for testing only. See `keys/README.md`.

## Regeneration

Vectors are generated by a deterministic Rust binary:

```bash
# From workspace root:
cargo run -p receipt-core --bin vcav-generate-vectors
```

Running the generator produces identical output on every invocation (no randomness). If canonicalization or signing logic changes, vectors must be regenerated and the diff reviewed.

## Verifier Integration

```bash
cargo run -p verifier-cli --bin vcav-verify -- \
  data/test-vectors/receipt_v2_vector_01.json \
  --pubkey data/test-vectors/keys/vault.pub \
  --schema-dir ./schemas
```

Expected output: `OK`
